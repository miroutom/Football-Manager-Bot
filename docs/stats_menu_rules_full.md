# Правила: топ-100, стата сезонов, голеадоры по клубам

Полная формулировка из чата (май 2026). Краткая сводка для разработки — в [`stats_display_rules.md`](stats_display_rules.md).

Реализация: `utils/stats_history_agg.py`, `utils/common_db.py`, `player_stats.py`, `utils/player_transfer.py`, `utils/player_discipline.py`.

---

## Исходные правила (текст из чата)

### Топ-100

Отображается **полная статистика игрока за все сезоны** в **одной строке**, указывается его **последний (текущий) клуб**.

Пример: Смолов в 1-м сезоне играл за Динамо, во 2-м — за Ювентус. В топ-100: **Смолов · Ювентус · (статистика)**.

### Стата сезонов

**1. Сезон N — как в архиве сезона**

Если игрок провёл сезон в клубе А, в этом сезоне он отображается **именно в этом клубе** (как в БД `db/season_N/`).

- Смолов провёл весь 1-й сезон в Динамо → в «стата сезонов» → «сезон 1» — из `season_1`, клуб **Динамо**.
- 2-й сезон в Ювентусе → в «сезон 2» — из `season_2`, клуб **Ювентус**.
- «Стата сезонов» → **«за всё время»** — общая статистика игрока с **последним (текущим) клубом**, как в топ-100.

**2. Межлиговой переход в одном сезоне — две строки в лигах**

Игрок перешёл из клуба лиги А в клуб лиги Б в **одном** сезоне → в отчёте по сезону **две строки** (и в БД сезона тоже).

Пример: Батши в 2-м сезоне сначала Краснодар (РПЛ), потом Вольфсбург (Бундеслига).

- «Стата сезонов» → «сезон 2»: **две строки** — стата за Краснодар и за Вольфсбург (в каждой нац. лиге по одной строке).
- Вкладка **«Все чемпионаты»** за этот сезон — **одна строка** с **общей** статистикой и **последним (текущим) клубом**.

*Уточнение по ЛЧ (см. ниже): в отображении ЛЧ за сезон — **одна** строка с последним клубом и суммой по ЛЧ, а не две.*

**3. Переход внутри одной лиги — одна строка**

Игрок перешёл из клуба лиги А в другой клуб **той же** лиги в одном сезоне → **одна строка**, клуб = **последний (текущий) в этом сезоне**, стата **суммарная**.

Пример: Ангисса во 2-м сезоне Наполи → Милан (Серия А). В БД 2-го сезона везде одна строка: **Ангисса · Милан · (статистика)** (1+0 в Наполи и 0+1 в Милане → в отчёте лиги **1+1 Милан**).

### Голеадоры по клубам

**1.** Если игрок забил или отдал голевую **в сезоне**, играя за клуб, он **должен отображаться** в голеадорах этого клуба **несмотря на последующий переход**.

- Батши отдал голевую за Краснодар в лиге → **обязан** быть в голеадорах Краснодара (лига).
- В ЛЧ за Краснодар 0 действий → в голеадорах ЛЧ Краснодара **не показывать**.

**2.** Голевые действия в новом клубе → показ в голеадорах **нового** клуба в **соответствующем турнире** (лига / ЛЧ отдельно).

### Карточки при трансфере (исходная формулировка)

- Переход **в другую лигу**: жёлтые и красные в **национальной лиге** обнуляются (см. уточнение ниже — в БД история остаётся, сбрасывается **накопление**).
- В **ЛЧ** при межлиговом переходе — **не** обнулять накопление ЛЧ.
- Переход **внутри одной лиги** (клуб А → клуб Б той же лиги): жёлтые и красные в SQLite **не** обнуляются.

### Перенос полевой статы при трансфере

- Старая строка в клубе «откуда» **сохраняет** матчи / голы / передачи (для голеадоров и истории сезона).
- В клубе «куда» — **новая** строка с **нулевой** полевой статой в новом сезоне.

## Уточнения (ответы на вопросы 1–5)

| № | Вопрос | Ответ |
|---|--------|--------|
| 1 | Что такое «текущий / последний клуб»? | Клуб из **активного сезона** (`season_state.json`, рабочие `db/season_N/`). |
| 2 | «Все чемпионаты» за сезон при межлиговом переходе | **Сумма** всего за сезон (все нац. лиги + ЛЧ). Клуб в подписи — **последний** (напр. Вольфсбург). В `common.db` хранится **вся** стата сезона: 2+2 в АПЛ, 0+1 в БЛ, 1+1 в ЛЧ → в common **3+4**. |
| 3 | ЛЧ за один сезон при двух клубах | В отчёте **всегда одна строка** — **последний клуб**, стата **суммарная** по ЛЧ. Пример: 0+1 за Краснодар, 1+0 за Вольфсбург → в топе ЛЧ сезона 2: **1+1 Вольфсбург**. |
| 4 | Ангисса (Наполи → Милан) | Одна строка в лиге сезона со **сложенной** статой; в голеадорах Наполи — если были Г/А там, в Милане — если были Г/А там. |
| 5 | Карточки | **`yellow_cards` / `red_cards` в SQLite** — **не** обнуляем (история). **Накопление к 4-й жк** (`yellow_cycle` в JSON) — **сбрасываем** при межлиговом трансфере в **обеих** нац. лигах и для активного сезона; **между сезонами** циклы жк тоже с **0**. ЛЧ: накопление на игрока, при межлиговом переходе цикл ЛЧ **не** сбрасывать. |

## Сводная таблица

| Раздел | Правило |
|--------|---------|
| **Топ-100** | Одна строка на **полное имя** в synced (не по фамилии): сумма за все сезоны; клуб и позиция = **активный сезон** (`name` + позиция, без `left_team`). |
| **Стата сезонов → сезон N** | Строки как в `db/season_N/`. Межлига в сезоне → **две строки** в каждой нац. лиге (Батши). Внутри одной лиги → **одна строка**, текущий клуб, стата **сумма** (Ангисса). |
| **Стата сезонов → за всё время** | Как топ-100: слияние по **полному имени**, не по фамилии; клуб из активного сезона. |
| **Стата сезонов → все чемпионаты (один сезон)** | Одна строка: **полная** стата лига+ЛЧ за сезон, клуб = последний в сезоне. |
| **Стата сезонов → ЛЧ (один сезон)** | Одна строка на игрока: сумма по ЛЧ, клуб = **последний** в `champions_league.db`. |
| **Голеадоры по клубу** | Строки с `team = клуб` и **Г>0 или А>0** в **этом** турнире; после ухода старая строка в старом клубе **остаётся**. |
| **Трансфер: поле** | Старая строка со статой; новая — с нуля. |
| **Трансфер: карточки** | SQLite жк/кк — история; `yellow_cycle` — сброс при смене нац. лиги и на новый сезон. |
| **Идентичность (`person_id`)** | Один человек = один `person_id` в `db/players_registry.db`; трансфер копирует id, новый игрок — новый id; backfill архивов — отдельные фазы. |

| Меню / режим | БД |
